Прототип «Мира» (`~/what-affects-me`): движок дневника (`wam/`), локальная
страница-диалог (`web/server.py` + `web/page.html`), Telegram-бот (`bot/`),
придуманный дневник для показа (`demo/`), тесты (`tests/`).

**Стиль.** Докстринги и комментарии по-русски и всегда про «почему», а не про
«что»: почти каждый комментарий в коде описывает случай из жизни, который
раньше ломался («раньше половина сказанного пропадала», «прежний потолок в
миллион спасал только от падения»). Новый код без такого объяснения выглядит
чужим. Имена тестов - фразы по-английски, докстринг теста - по-русски и тоже
про случай, который проверяется.

**Как устроено.** Стандартная библиотека и `pytest`, никаких фреймворков;
`requirements-dev.txt` содержит только pytest. Никаких ключей в коде: разборщик
речи выбирается из окружения (`wam/llm.py: available_engine`), при отсутствии
ключа работают правила (`RuleExtractor`).

**Запуск.** Тесты: `python3 -m pytest -q` из корня (около полминуты, на
19.08.2026 было 107 зелёных, стало 119). Страница: `python3 -m web.server` ->
http://127.0.0.1:8765.

**Грабли.**
- Под замком дневника (`Diary.lock`) нельзя делать сетевых вызовов - разбор
  речи моделью делается до взятия замка.
- `Diary.reset()` чистит ленту, но не сбрасывает `seq`, а `DiaryStore` в
  `web.server` один на процесс: в тестах номера сообщений сквозные между
  тестами, поэтому не проверяйте `seq == 1`.
- Тесты диалога обязаны задавать `parser=dialog.Parser()` явно, иначе на
  машине с ключом модели в окружении прогон полезет в сеть.
