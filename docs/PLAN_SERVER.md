# PLAN_SERVER.md — «Мира» как сервис на https://mira.ambarik.ru

## Что делаем
Делаем из однопользовательского прототипа сервис для людей на сервере timeweb. У каждого свой дневник. Вход через общего Telegram-бота сервиса: у бота один токен из окружения, чат с пользователем связывается автоматически. Данные о здоровье защищены по 152-ФЗ: проверка входа и владельца в каждом запросе, согласие, удаление своих данных, шифрованные бэкапы. Локальный режим 127.0.0.1 работает как сейчас, существующие 320 тестов остаются зелёными.

## 1. Вход
**Одноразовая ссылка от бота.**
- Человек пишет боту `/start`. Бот заводит пользователя по `from.id` (в личном чате он равен `chat_id`) и присылает ссылку `https://mira.ambarik.ru/login#t=<32 байта secrets.token_urlsafe>`. Ссылка действует 10 минут и срабатывает один раз. Отправлять её с `link_preview_options.is_disabled=true`.
- Токен стоит после `#`. Эта часть адреса на сервер не уходит, значит не попадает в логи nginx-proxy, а превью-боты её не «съедают». Скрипт страницы `/login` читает токен и отправляет `POST /auth/login {token}`. Сервер находит sha256 токена в базе, гасит его, ставит cookie сессии и убирает `#` из адреса через `history.replaceState`.
- Вход повторно — снова `/start` или `/login` в боте.

Другие варианты, одной строкой:
- **Telegram Login Widget** — нужен домен в BotFather, чужой скрипт с telegram.org (CSP) и проверка HMAC; сложнее при той же пользе.
- **Mini App (initData)** — хорошо в будущем, но меняет весь интерфейс.
- **Почта или телефон** — нужны SMTP/SMS и капча, это лишний сбор ПДн.

## 2. Бот сервиса
- Один процесс: веб-сервер и опрос бота (`getUpdates`) в потоке одного процесса, как сейчас устроен `TelegramRunner`. Токен берётся только из `TELEGRAM_TOKEN`. Если токена нет, сервер работает без бота (решение 11.11.2026, см. ниже); токен не той формы - ошибка при запуске.
- Привязка: при `/start` дневник получает ключ `u:<user_id>`, в таблицу `chats` записывается `chat_id → u:<id>`. Код привязки (`/telegram/code`, `bind`) в режиме server не используется.
- Пока человек не дал согласие, бот ничего не записывает. Он отвечает: «сначала подтвердите согласие» и даёт кнопку (inline `callback_data=consent`) или ссылку на страницу согласия.
- В режиме server гостевых дневников нет. Ветку `_forget_guests` для ключей `u:*` отключить, иначе дневники будут удаляться через 7 дней.
- Новые команды: `/login` (новая ссылка), `/delete` (удалить всё, с подтверждением), `/export` (ссылка на выгрузку на странице).
- Напоминания хранить в SQLite (таблица `reminders`). Потолок `MAX_CHATS=200` в режиме server заменить на число пользователей.
- Один токен — один процесс. Для разработки нужен отдельный тестовый бот, иначе прод и локальный запуск будут отнимать друг у друга `getUpdates`.

## 3. Что убрать со страницы в режиме server
- **Убрать:** поле токена и кнопки «подключить/отключить бота» (`tg-token`, `/telegram/connect`, `/telegram/disconnect`, `/telegram/code`), панель кода привязки, `has_env_token`. На их место — строка «Telegram подключён: @user» и кнопка «Выйти».
- **Оставить:** «Начать заново» (`/reset`) как «Очистить ленту» - ссылка в шапке разговора, с подтверждением. Удаление записей — отдельная кнопка (см. п. 4).
- **Придуманный дневник:** карточками в блоке «Так это будет выглядеть: пример на придуманном дневнике» раздела «Что Мира заметила» (`GET /insights/example`, срок только из списка). Он один на всех, только для чтения и без ПДн; кэш `_CACHE` общий. Подпись «пример, не ваши данные».
- **Добавить:** «Мои данные» — выгрузка (уже есть `/export`), «Удалить всё» (ввести слово УДАЛИТЬ), «Выйти», ссылка на политику.
- Сервер сообщает режим в `/state` (`mode: "server"`), страница прячет блоки по нему. Отдельный HTML не нужен.

## 4. Безопасность
- **Режимы.** `MIRA_MODE=local` (по умолчанию): всё как сейчас, `WEB_KEY`, 127.0.0.1, без входа. `server`: адрес 0.0.0.0 внутри контейнера, разрешённый хост из `MIRA_PUBLIC_HOST=mira.ambarik.ru`.
- **Владелец записи.** В обработчике всё сводится к `key = self._user_key()`. Все `STORE.get(WEB_KEY)` (`_say`, `_summary_step`, `_set_city`, `_weather_today`, `_food_step`, `_export`, `/state`, `/reset`) получают `key` параметром. Ключ берётся только из сессии, никогда из тела запроса. Без сессии ответ 401 на всё, кроме `/`, `/login`, `/auth/login`, `/privacy`, `/healthz`.
- **Cookie.** `__Host-mira_sid`, `HttpOnly; Secure; SameSite=Lax; Path=/`. В базе только sha256 сессии. Срок 30 дней скользящий, при выходе и удалении сессия гасится.
- **CSRF.** Проверки `Origin` и `Sec-Fetch-Site` в `_ours()` сверять с `MIRA_PUBLIC_HOST`. Плюс токен CSRF, привязанный к сессии: отдаётся в `/state`, страница шлёт его в `X-CSRF` на каждый POST. POST без `Content-Type: application/json` отклонять.
- **Лимиты** (в памяти, по сессии и по IP; IP из `X-Forwarded-For`/`X-Real-IP` только от nginx-proxy): `/auth/login` 10/мин с IP; `/say` 20/мин и 300/сутки на человека; `/weather` 10/час; бот 30 сообщений/мин на чат.
- **Логи.** Никаких текстов, городов, фактов, токенов. В боте писать тип исключения и короткий id (8 знаков sha256), без `str(exc)`. Логи docker ограничить `max-size`.
- **Согласие.** При первом входе — экран согласия на обработку данных о здоровье; без «Согласен» доступа к дневнику нет. В `users`: `consent_at`, `consent_version`. Страница `/privacy`: оператор, цели, срок хранения, как удалить.
- **Удаление.** `POST /account/delete` и `/delete` в боте удаляют дневник, чаты, напоминания, сессии и пользователя. В политике: из бэкапов данные уходят через 14 дней.
- **Срок хранения** неактивных аккаунтов — решает владелец (предложение 12 месяцев).
- **LLM.** На сервере `WAM_ENGINE=yandex`, обязательно заголовок `x-data-logging-enabled: false`; модель из `YANDEX_MODEL` (по умолчанию `yandexgpt-5.1/latest`, `yandexgpt-lite` отключают 15.11.2026). Нет ключа — правила без ИИ. Anthropic и GigaChat на сервере не включать.
- **Хранилище.** Путь к базе из `MIRA_DB`. Новые таблицы через `CREATE IF NOT EXISTS`: `users`, `sessions`, `login_tokens`, `reminders`. База 600, каталог data 700.

## 5. Деплой (по образцу выставочного бота)
- **Dockerfile:** `python:3.14-slim`, только stdlib, `COPY wam bot demo web`, пользователь uid 10001, `CMD python -m web.server`; `.dockerignore`: `.diary.db*`, `.env*`, `tests`, `docs`, `.git`.
- **docker-compose.yml:** `env_file: .env`, `expose: 8765`, `VIRTUAL_HOST`/`VIRTUAL_PORT`/`LETSENCRYPT_HOST`=mira.ambarik.ru, сеть `samozanyatiy_bot_webnet` (external), `./data:/app/data`, `mem_limit: 384m`, `restart: unless-stopped`, `no-new-privileges`, `cap_drop: ALL`, `read_only` + `tmpfs /tmp`, логи 10m×3.
- **`/healthz`** без данных.
- **.env (600)**: `MIRA_MODE`, `MIRA_PUBLIC_HOST`, `MIRA_DB`, `TELEGRAM_TOKEN`, `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `YANDEX_MODEL`, `WAM_ENGINE`, `LETSENCRYPT_EMAIL`. В репозиторий только `.env.example` с пустыми значениями — репозиторий публичный.
- **Бэкап:** `tools/backup-mira.sh` в каталоге бэкапов на сервере, по образцу бэкапа выставочного бота (AES-256 pbkdf2, 14 дней, проверка расшифровки и `integrity_check`, копия на второй сервер в `backups/mira/`), cron `50 3 * * *`, ручной запуск перед каждой выкладкой.
- **Сервер:** `git clone` в каталог сервиса, `data` chown 10001 chmod 700, записать в журнал сервера (RUNBOOK) и в список серверов владельца.

## Риски
- Утечка между пользователями, если останется `WEB_KEY` или ключ из тела запроса — тест «два пользователя» на каждый эндпоинт.
- Гостевая чистка удалит дневники людей, если её не отключить для `u:*`.
- Все дневники в памяти; на сервере свободно ~0,9 ГБ — на сотни людей хватит, дальше подгрузка по требованию.
- Один токен — один процесс: локальный запуск с боевым токеном ломает прод-бота.
- Telegram — иностранный сервис, данные о здоровье идут через него (решение владельца).
- Откат: таблицы только добавляются; `git checkout <прежний>` + `docker compose up -d --build`.

## Решения владельца (11.11.2026)
1. Оператор ПДн пока не определён — в политике плейсхолдер из `MIRA_OPERATOR`, текст помечен как черновик. До ответа людей на пилот не пускаем.
2. Согласие галочкой в браузере на время пилота — принято.
3. Telegram как канал для данных о здоровье — принято, указать в политике.
4. Неактивные аккаунты (нет входа и новых записей) удаляются через 12 месяцев (`MIRA_RETENTION_DAYS=365`).
5. Лимит запросов к ИИ — 300 в сутки на человека (`MIRA_DAILY_LIMIT=300`).

## Решение владельца 11.11.2026: можно без Telegram
Сделано поверх этапов 1-5:
- Кнопка «Начать без Telegram» (`POST /auth/new`): человек без `tg_id`, `user_id` отрицательный случайный, сразу сессия, затем согласие и дневник. Потолок 5 новых в час с адреса. Без согласия такой аккаунт удаляется через 7 дней, как и пришедший из бота.
- Личный код: 16 знаков из азбуки без похожих символов, группами по 4 (~79 бит). Выдаётся при создании, в «Мои данные» - новый по кнопке (прежний гаснет; показать прежний нельзя, хранится только хэш). В `users`: `code_salt`, `code_hash` (scrypt n=2^14, r=8), `code_index` - 4 знака sha256 для поиска. Вход - `POST /auth/code`: 10 попыток в минуту с адреса и 100 в минуту на всех; ответ на неверный и несуществующий код одинаковый.
- Бот необязателен: без `TELEGRAM_TOKEN` сервис стартует, блоки Telegram на странице скрыты. С ботом человек без Telegram получает в «Мои данные» ссылку `t.me/<бот>?start=<токен>` (`POST /account/telegram`, таблица `link_tokens`, 10 минут, один раз); `/start <токен>` привязывает чат к этому человеку (`users.tg_id`). Чат, у которого уже свой дневник, не склеивается.
- Бот ищет человека по `users.tg_id` (`Accounts.by_telegram`), а не считает номер чата номером человека. Пришедшие из бота раньше получают `tg_id = user_id` при запуске.
- Текст политики дополнен, `CONSENT_VERSION` поднят до `2026-11-11-черновик-2`.

### Правки по аудиту (11.11.2026)
- Привязка Telegram в два шага: `/start <токен>` → бот шлёт `https://<адрес>/link#t=<второй токен>`, `POST /account/telegram/confirm` принимает его только от той сессии, что выпустила первый (`link_tokens.sid_hash`). Привязанный чат пишет в дневник только после согласия, нажатого в самом чате (`users.tg_consent_version`, `Accounts.has_chat_consent`).
- scrypt: не больше 2 одновременно (`SCRYPT_SLOTS`, ожидание 2 с, иначе 503); при промахе по отпечатку - один фиктивный scrypt; новый код 5 раз в час на человека, смена кода закрывает остальные сессии.
- Потолки по IPv6 - на сеть /64; создание - ещё 100 в час на всех и не больше 2000 без согласия; с сайта без согласия удаляются через сутки.
- Политика: про IP (только в памяти, не дольше часа; журнал прокси - `MIRA_PROXY_LOG_DAYS`) и про выключенный голос.
- Миграция tg_id не трогает занятые номера, в журнал - только число.
